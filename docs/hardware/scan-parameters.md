# 参数与扫描路径

[返回项目首页](../../README.md) · [首次运行](wiring-and-first-run.md) · [常见问题](troubleshooting.md)

## 1. 参数文件在哪里

所有日常参数集中在：

`firmware/Core/Inc/snake_scan_config.h`

该文件顶部的“用户常用参数”是更换掩模版时主要修改的区域。商家协议函数位于 `BSP/Emm_V5.c`，一般不要改动。

## 2. 控制扫描范围的变量

```c
#define MASK_SCAN_WIDTH_UM       100000UL
#define MASK_SCAN_HEIGHT_UM      100000UL
#define SCAN_LINE_STEP_UM          2000UL
#define SCAN_SPEED_UM_PER_SEC   1000UL
```

- `MASK_SCAN_WIDTH_UM`：每条水平扫描线的长度，固件单位 μm，界面输入 mm。
- `MASK_SCAN_HEIGHT_UM`：整个扫描过程中垂直轴累计上升距离，固件单位 μm，界面输入 mm。
- `SCAN_LINE_STEP_UM`：每完成一条水平线后，垂直轴上升距离，固件单位 μm，界面输入 mm。
- `SCAN_SPEED_UM_PER_SEC`：两轴线速度，单位 um/s；1000即1 mm/s。

### 速度修改示例

当前水平轴和垂直轴共用同一个线速度参数：

```c
/* 0.5 mm/s */
#define SCAN_SPEED_UM_PER_SEC    500UL

/* 1.0 mm/s，当前默认值 */
#define SCAN_SPEED_UM_PER_SEC   1000UL

/* 2.0 mm/s */
#define SCAN_SPEED_UM_PER_SEC   2000UL
```

实际只保留其中一条定义，不能同时定义三次。程序会使用丝杆导程自动换算：

```text
电机转速RPM = 线速度(um/s) x 60 / 丝杆导程(um/圈)
```

T6x1导程为1000 um/圈，因此1 mm/s对应60 RPM，2 mm/s对应120 RPM。水平、垂直运动超时时间也会随速度自动计算，不需要修改 `main.c` 或 `Emm_V5.c`。

如果以后需要两轴使用不同速度，应新增水平速度和垂直速度两个参数并修改运动函数；当前两轴使用同一个速度。

程序自动计算：

```text
水平扫描线数 = MASK_SCAN_HEIGHT_UM / SCAN_LINE_STEP_UM
```

高度必须能被行距整除，否则编译会报错，防止扫描到一半出现不足一行的情况。

## 3. 三种常见掩模版

### 100 x 100 mm

```c
#define MASK_SCAN_WIDTH_UM       100000UL
#define MASK_SCAN_HEIGHT_UM      100000UL
#define SCAN_LINE_STEP_UM          2000UL
```

结果：50条水平线，垂直累计移动100 mm。

### 100 x 50 mm

```c
#define MASK_SCAN_WIDTH_UM       100000UL
#define MASK_SCAN_HEIGHT_UM       50000UL
#define SCAN_LINE_STEP_UM          2000UL
```

结果：25条水平线。因为是奇数条，扫描结束时水平滑台位于起点的另一侧。

### 50 x 100 mm

```c
#define MASK_SCAN_WIDTH_UM        50000UL
#define MASK_SCAN_HEIGHT_UM      100000UL
#define SCAN_LINE_STEP_UM          2000UL
```

结果：50条水平线，扫描结束时水平滑台回到与起点相同的一侧。

## 4. 水平运动方向

```c
#define X_FIRST_PASS_DIRECTION       1U
#define X_ALTERNATE_PASS_DIRECTION   0U
#define Y_STEP_DIRECTION              0U
```

ZDT Emm命令中0和1分别代表两个电机旋转方向。方向和滑台的物理左、右关系取决于电机安装朝向，因此程序使用“第一条方向”和“交替方向”，不把它们硬编码成左或右。

第一条水平线使用方向 1，第二条使用方向 0，之后逐条交替。Y 轴始终沿 `Y_STEP_DIRECTION` 步进；文中的“上移”指这一配置方向。

如果以后更换电机安装方向，只交换：

```c
#define X_FIRST_PASS_DIRECTION       0U
#define X_ALTERNATE_PASS_DIRECTION   1U
```

不要通过交换地址1和地址2来修正方向。

## 5. 电机与丝杆参数

```c
#define MOTOR_FULL_STEPS_PER_REV   200UL
#define MOTOR_MICROSTEP             16UL
#define LEAD_UM_PER_REV           1000UL
```

- 1.8°电机为每圈200整步。
- 两台驱动器的 `MStep` 必须都为16。
- T6x1丝杆按每圈移动1 mm计算，因此导程为1000 um/rev。

细分不一致会导致位移换算错误；丝杆导程不一致会导致位移与线速度换算错误。默认参数下，每圈 200 × 16 = 3200 脉冲，每毫米 3200 脉冲。

## 6. 软件安全行程

```c
#define X_AXIS_MAX_SAFE_TRAVEL_UM  100000UL
#define Y_AXIS_MAX_SAFE_TRAVEL_UM  100000UL
```

这两个数值是软件允许的最大相对运动范围，不是自动测量出来的机械限位。更换滑台后，应先实测安全行程，再修改这里。掩模版宽度或高度超过安全行程时，程序会直接编译失败。

## 7. 扫描路径细节

程序按以下规则执行：

1. 水平轴按照第一条方向运动一个掩模版宽度。
2. 垂直轴上移一个行距。
3. 水平轴反向运动相同宽度。
4. 垂直轴再次上移一个行距。
5. 重复直到垂直累计移动量达到掩模版高度。

最后一条水平线完成后，垂直轴再移动一次行距，使垂直累计位移等于设置高度。水平线的相对 Y 坐标为 0、行距、…、高度减行距；最终 Y 坐标为设置高度，该高度处没有额外水平扫描线。

例如宽 10 mm、高 4 mm、行距 2 mm 的路径（X 正方向按第一条运动定义）：

```text
起点 (0,0) → (10,0) → (10,2) → (0,2) → 终点 (0,4)
           X 第一条     Y 步进     X 第二条    Y 步进
```

偶数条水平线结束后，X 回到起始侧；奇数条结束后，X 停在另一侧。最终恢复起点需要另外执行，不能直接以终点开始下一轮。

## 8. 时间估算

忽略通信查询和换轴延迟时：

```text
水平总距离 = 掩模版宽度 x 水平扫描线数
垂直总距离 = 掩模版高度
理想时间 = (水平总距离 + 垂直总距离) / 线速度
```

在1 mm/s、行距2 mm时：

| 范围 | 理想运动时间 |
|---|---:|
| 100 x 100 mm | 约5100秒，85分钟 |
| 100 x 50 mm | 约2550秒，42.5分钟 |
| 50 x 100 mm | 约2600秒，43.3分钟 |

实际时间会略长，因为每次换轴包含300 ms延迟和状态查询时间。

## 9. 四个渐进工程

每次修改参数或接线后，都建议按顺序验证：

1. `01_COMM_CHECK_NO_MOVE.uvprojx`：只通信，不运动。
2. `02_1MM_MOTION_TEST.uvprojx`：两条1 mm水平线，每条后Y移动1 mm。
3. `03_10MM_MOTION_TEST.uvprojx`：两条10 mm水平线，每条后Y移动2 mm。
4. `04_ACTUAL_SNAKE_RUN.uvprojx`：使用实际掩模版参数。

四个工程编译的是同一套源代码，只通过 `SCAN_STAGE` 编译宏选择测试阶段。

## 10. 状态灯和错误码

野火小智板PA1红灯为低电平点亮：

- 运动工程在通信检查成功后，每秒闪一次，共 5 次，然后启动运动。
- 通信检查工程通过后直接常亮。
- 通信检查成功或扫描完成后常亮。
- 故障时循环闪烁错误码。

| 闪烁次数 | 含义 |
|---:|---|
| 1 | 水平轴地址2无应答 |
| 2 | 垂直轴地址1无应答 |
| 3 | 水平轴运动命令、到位检测或超时错误 |
| 4 | 垂直轴运动命令、到位检测或超时错误 |
| 5 | 一次性地址设置失败 |
| 6 | 水平轴位置计数器清零失败 |
| 7 | 垂直轴位置计数器清零失败 |

扫描流程检测到故障后会尝试广播立即停止命令，然后按“每次亮 200 ms、灭 200 ms，一组后停 1200 ms”的节奏重复错误码。停止命令保留电机保持力矩；通信断开时不能保证命令送达。底层 HAL 初始化失败进入 `Error_Handler()`，不一定有上述错误码。


## 11. 参数边界与到位判断

界面支持最多3位小数毫米，保存为整数微米，例如 `0.5 mm → 500UL`、`0.1 mm → 100UL`。不要把小数直接写进 `_UM` 宏。换算采用64位中间结果，命令脉冲和运行行号采用32位整数，并检查溢出。

距离必须精确对应整数脉冲，不做静默舍入。默认200整步/圈、16细分、1000 μm/圈时，界面可设的最小正行距是 **0.005 mm（5 μm、16脉冲）**，宽度和行距必须是它的整数倍；高度必须能被行距整除。这是“整数微米输入”和“整数脉冲”共同决定的软件步长，**不是机械定位精度，也不是驱动器一脉冲的极限**。单脉冲理论位移仍为0.3125 μm；如需逐脉冲设置，需另行增加脉冲输入模式，不能把0.0003125 mm直接填入本界面。

| 界面行距 | 固件 `SCAN_LINE_STEP_UM` | 默认硬件脉冲数 | 80 mm高度的行数 |
|---:|---:|---:|---:|
| 0.5 mm | 500UL | 1600 | 160 |
| 0.1 mm | 100UL | 320 | 800 |
| 0.05 mm | 50UL | 160 | 1600 |
| 0.005 mm | 5UL | 16 | 16000 |

例如宽80 mm、高80 mm、行距0.5 mm、速度2 mm/s，纯运动时间约107.3分钟；行距0.1 mm时约534分钟，此外每次移动至少两次500 ms状态轮询和300 ms换轴等待。小行距显著增加采集时间，不能用纯运动时间分行。请把实际行距同步填写到重构配置，保存逐行记录；光斑尺寸和机械回差仍会限制成像分辨率。

正式范围受安全行程宏约束，1 mm和10 mm测试工程仍采用固定范围。首次验证小行距可以在正式工程填宽1 mm、高1 mm、行距0.1 mm，核对方向、10次Y步进与累计1 mm位移后再扩大范围。

速度命令按整数 RPM 四舍五入，某些自定义速度会有量化误差。默认导程下，500、1000、2000 um/s 分别对应 30、60、120 RPM。`SCAN_ACCELERATION=0` 表示直接以设定速度启动；增加速度前需复核负载和运动稳定性。

状态查询间隔为500 ms。到位判断要求：本次收到接收确认 `FD 02` 或观察到未到位状态；经过该距离按实际命令转速计算的名义运动时间；连续两次查询到位。小运动即使在首次查询前结束，也可通过接收确认和两次状态查询完成等待。单独的 `FD 9F` 不再直接结束等待，丢失运动确认也不会重发相对运动命令。

**两台驱动器的控制命令应答 Response 应设为 Receive（接收应答）或 Both（接收和到位应答）。** None/Reached 模式下，短运动可能既没有 `FD 02` 又来不及被观察到运动中，程序会超时报错3/4；这是证据不足时停止，不是自动假定运动成功。通讯仍使用现有固定0x6B校验，没有命令序号与实测位置核验；这次修改不证明偶发快速横移已解决。

`RESET_MOTOR_COUNTERS_AT_START=0` 为默认值。设为 1 只清零驱动器内部位置计数，不执行机械回零。清零、地址设置等维护功能不属于更换掩模版所需操作。

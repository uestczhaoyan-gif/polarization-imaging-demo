# 再次快速横移与 RESET 异常

用户在 80×80 mm、2 mm/s、暗环境的新测量中再次观察到一次快速水平移动，并报告修改接线后 RESET 不好用、重新下载才能运行。本次记录与 [加速排查](motion-anomalies.md) 配合阅读。

## 目前能下的结论

不能断言“软件完全没有问题”，也不能据此认定驱动器坏了。

- 正常调用链每条 X 横扫仅发送一次位置命令；2 mm/s 在 1 mm 导程下转换为 120 RPM，速度字段为 `00 78`。Y 方向只影响其方向字节。代码没有在长行中途主动提高转速的分支，也不在查询失败后重发位置命令。
- 存在实际的软件健壮性缺口：DMA 接收缓冲在主循环读完前已重启写入；到位依赖单帧/单次状态，缺少位置核验；DMA 发送错误没有向上层传递。
- 特别是 `FD 9F` 被立即当成完成。如果收到迟到的旧到位帧，或已经看到运动后误收到到位状态，扫描层可能提前开始下一段。这是待加固的路径，**尚未证明它造成了所见的加速**。主机故障注入验证见下文。
- 当前读到的仓库头文件仍为 100×100 mm、1 mm/s。没有取得这次实际烧录的 80×80 mm、2 mm/s 配置及 HEX，不能把仓库检查等同于对事发固件的完整验证。

## RESET 应如何区分

**MCU 的 RESET 不是整台设备的急停，也不会让外置电机驱动器自动复位。** 驱动器已经收到的一条运动命令可能在 MCU 复位期间继续执行；不要在带负载运动中按 RESET 作为停机测试。代码重新启动后也会从当前机械位置再次发出整段运动。

先停止试验并关闭电机动力，保持 MCU 正常供电。不要为了判断按钮而反复下载正式长行程程序。

| 观察/检查 | 区分什么 |
|---|---|
| 按 RESET 时 NRST 是否被拉低，松开后是否回到约3.3 V | 按钮、复位线或下载器是否实际控制了复位。万用表仅适合按钮保持时检查；瞬态需示波器 |
| BOOT0 是否按板卡说明保持低电平 | 正常从内部 Flash 启动；不要把 BOOT 跳帽和 J5 串口跳帽混淆 |
| 电机动力关闭后，断开 DAP 的 RST 线再检查 MCU 的按钮 | 下载器/接线是否拉住复位；变更接线前先断电 |
| 控制板3.3 V是否稳定、地线是否可靠、外设是否通过信号线反向供电 | 供电/接线问题；不把电机动力电压接入逻辑引脚 |
| 上电/复位后红灯状态：有无5次倒计时、是否1/2次循环闪烁 | 有倒计时说明程序已经运行；1/2次为轴通信检查失败，不能说是按钮坏了 |
| 完全停机并恢复安全起点后，正常断电上电能否运行，而只按 RESET 不行 | MCU复位、驱动器残留状态与完整上电顺序的差异 |

本项目没有将 NRST 配成普通输出，也没有自改 Flash 或在运行中保存“已经扫描过”的持久标志。`__HAL_AFIO_REMAP_SWJ_NOJTAG()` 保留 SWD，不是关闭硬件 RESET。启动失败仍可能进入初始化错误循环；仅从“不运动”不能判断 MCU 没复位。

引脚、启动模式和复位电气行为可核对 [ST 官方 STM32F103x8/xB 数据手册](https://www.st.com/resource/en/datasheet/stm32f103r8.pdf)。实际跳帽位置按本板原理图核对，不能套用别的开发板照片。

## 可以做的对照试验

先解决复位/接线异常，再让商家提供适配该型号的单轴有限距离例程。保持同一电源、负载、120 RPM与安全短行程，对比本项目和厂商例程；一次只变一个因素。若两边都出现，驱动器/机械/供电方向更值得检查；若只有本项目出现，集中检查通信、反馈和烧录版本。一次正常不能排除偶发故障。

不建议现在通过调高电流、关闭保护、改PID或“加延时”宣布解决。代码可逐项加固为稳定收帧、发送状态检查、到位位置核验及带时间日志，再经过 Keil 编译和短行程实测；本次没有偷偷替换运动固件。

## 主机检查怎样复现

在有 GCC 的机器上，从项目根目录运行：

```bash
python scripts/audit_motion.py
```

脚本从当前 C 文件提取真实函数，在临时目录以2000 μm/s配置编译，模拟正常50秒长行、丢失确认、查询完全丢失、迟到到位帧和错误到位位。它检查命令字节和是否重复发运动命令，并用 `REPRODUCED` 明确标记可复现的提前结束等待缺口。绿色CI意味着检查按预期执行，**不表示缺口已修复，更不表示实机安全验证通过**。测试桩不模拟真实 DMA 时序、RS485线路或电机物理行为。

# 三组平移台实验

三个独立入口共用一套固件，每次生成一个新的、参数独立的工程文件夹。**生成文件不等于烧录成功，指令到位也不等于平台实际到位。** 本例程没有连接或控制源表。

| 入口 | 要回答的问题 | 默认实验 |
|---|---|---|
| [01 单/双向扫描](01_scan_modes/README.md) | 同向扫描是否减轻奇偶行错位？ | 2 × 1 mm、0.5 mm 行距、1 mm/s、单向 |
| [02 时间记录](02_motion_timing/README.md) | 每一段运动发生在什么时候？ | 同上，等待电脑 `g` 后启动并记日志 |
| [03 平台测试](03_stage_characterization/README.md) | 实际小位移、重复性及最高已验证平稳速度是多少？ | X 轴 1 mm 往返 3 次，每次停留 5 秒 |

## 明天按这个顺序使用

1. 准备 Python 3.10+（含 Tkinter）、Keil 和原来的下载器。实验二、三另需 **3.3 V 电平 USB 转 TTL 模块**及三根线，安装 `python -m pip install pyserial`。板上双 USB 不能直接替代这里的独立日志通道。
2. 在上述实验文件夹双击 `START.cmd`。没有自动找到 Python 时，选择自己的 `python.exe`。界面显示毫米；`settings.json` 和 C 头文件距离用整数微米，时间用毫秒。设置实际方向和可用行程。导程、细分、电机地址等沿用主工程配置，也可在 JSON 的 `scan` 中显式填写。
3. 点击“校验并生成独立工程”。新文件夹位于 `local/lab-projects/日期时间`，主工程和之前的实验副本不被覆盖。保留 `prepared-config.json` 和两份头文件。
4. 打开新文件夹的 `firmware/MDK-ARM/01_COMM_CHECK_NO_MOVE.uvprojx`，编译下载检查通信；用 `02_1MM_MOTION_TEST.uvprojx` 核对方向和余量。`03_10MM_MOTION_TEST.uvprojx` 是进一步的小行程扫描。**01 始终不运动，02/03 始终执行固定小行程扫描；单轴往返/阶梯参数仅在 04 生效。**
5. 正式实验打开新文件夹的 `04_ACTUAL_SNAKE_RUN.uvprojx`，重新编译下载。实验一默认无需电脑日志，上电/复位后倒计时启动；实验二、三和所有开启日志的配置会等待 `g`。每次实验只执行一轮，重新试验需要复位并建立新日志文件夹。
6. 实验二、三：打开日志收集器，选外接 USB-TTL 的 COM 口，**然后复位开发板**。收到 `BOOT` 和 `READY` 后输入 `g` 回车。不要给电机板 USART1 开电脑串口，也不要带电插拔电机线。
7. `RUN_END` 表示程序正常结束。保留最后的人工时间标记，等下一次时钟交换后输入 `q` 退出。中途 `!` 或 `q` 仅请求软件停止；串口断线、驱动异常时不能保证停止，需能及时切断电机电源。异常实验保留原始文件，标记失败，不当成成功数据。

生成的独立包也有 `START.cmd`，可继续生成新参数副本。若已在 Keil 手动改了头文件，先核对 `prepared-config.json` 与实际编译源文件；它不能证明你烧录的是哪个版本。

## 日志接线

根据本项目所用野火小智 STM32F103C8T6 双 USB 板原理图，板载 CH340 和现有电机通信使用 USART1（PA9/PA10）。新增日志使用 USART3：

| STM32 | 外接 USB-TTL |
|---|---|
| PB10 / USART3 TX | RXD |
| PB11 / USART3 RX | TXD |
| GND | GND |

模块与电脑连接。使用 **3.3 V TTL 电平**，不是 RS232 或 RS485。模块 VCC 不接；开发板按原方案供电。核对模块 TX 的实际逻辑电平。日志为 115200、8N1，无流控。通过设备管理器比较插入模块前后的 COM 列表确认端口。

## 每次必须留下的记录

- 日期、样品照片与起点、轴正方向、安装状态、负载、供电、润滑情况；测量仪器及分辨率。
- 实际烧录工程、代码版本、两份配置头文件、模式、宽高行距、速度/实际整数 RPM、细分、导程、加速度、次数、停留时间。
- 源表原始数据、每点时间（有就保存）、量程、积分时间及单位、触发/自动量程设置，不能把“0.1”直接当采样周期。
- 日志整个文件夹：`events.csv`、`raw.jsonl`、`pc_sync.csv`、`manual_marks.csv`、`session.json`，以及填好的实测位置表、异常录像。
- 任何失控/突然加速、卡顿、声音变化都记下对应时间/运动编号。先完成机械/线缆排查再扩大行程或速度；不要仅靠重构把异常掩盖掉。

## 代码从哪里看

运动顺序：`firmware/Core/Src/main.c` 的 `SnakeScan`、`Lab_AxisTest`；日志：`lab_io.c`；实验参数：`firmware/Core/Inc/lab_config.h`；独立工程生成：`tools/prepare_lab.py`；日志收集：`tools/collect_motion.py`。这些路径均相对当前包根目录。

验证边界：[软件验证记录](validation.md)覆盖软件路径、配置和日志分析，不能替代 Keil 实际下载、电气接线和平台机械测量。无直线位移传感器时，仍无法从日志恢复某次突然窜动的真实逐点轨迹。
